# タスク管理アプリ 要件定義書

## 1. 概要

### 1.1 目的
自分専用のシンプルなタスク管理アプリを作成する。Trello風に、タスクを「未着手・作業中・完了」の3つの進捗状況に分けて管理し、ドラッグ&ドロップで進捗を更新できるようにする。

本プロジェクトはスクールの課題として取り組むものであり、実務でのニーズ解決ではなく **学習目的** であることを前提とする。具体的には以下の学習を目的とする。

- 要件定義 → 画面設計・データ設計 → 実装 → 動作確認という開発の一連の流れを経験すること
- ドラッグ&ドロップ操作やlocalStorageを使ったデータ永続化など、フロントエンド技術の実装力を身につけること
- 要件定義書・設計書といったドキュメントを、実務を想定した体裁で作成する練習をすること

### 1.2 想定利用者
- 開発者本人のみ(1人で使用)
- ログイン機能・複数ユーザー対応は不要

### 1.3 開発背景
スクールの課題として着手。まずは要件定義を行い、その後設計・実装に進む。

## 2. ユースケース・操作フロー

### 2.1 ユースケース一覧

| ID | ユースケース名 | 概要 |
|---|---|---|
| UC-01 | タスクを新規登録する | 新しいタスクをボードに追加する |
| UC-02 | タスクの内容を編集する | 既存タスクのタイトル・説明・優先度・期限を修正する |
| UC-03 | タスクを削除する | 不要になったタスクを削除する |
| UC-04 | タスクの進捗を更新する | ドラッグ&ドロップでタスクを別の列に移動する |
| UC-05 | 同一列内でタスクの表示順を変える | ドラッグ&ドロップで並び替える |
| UC-06 | 期限切れ・期限間近のタスクを確認する | 強調表示されたタスクを一覧から把握する |

### 2.2 操作フロー詳細

#### UC-01 タスクを新規登録する
- 事前条件: ボード画面が表示されている
- 操作手順:
  1. 「未着手」列にある「+ タスクを追加」ボタン等を押下する
  2. タイトル・説明文・優先度・期限の入力フォーム(モーダル)が表示される
  3. 必須項目(タイトル・優先度)を入力し、「登録」ボタンを押す
- 事後条件: 「未着手」列の末尾に新しいカードが追加され、localStorageに保存される
- 代替フロー: タイトル未入力のまま登録しようとした場合、エラーメッセージを表示し登録しない

#### UC-02 タスクの内容を編集する
- 事前条件: 編集したいタスクのカードがボード上に存在する
- 操作手順:
  1. 対象カードをクリックする
  2. 編集モーダルが開き、現在の入力内容が表示される
  3. 内容を修正し、「更新」ボタンを押す
- 事後条件: カードの表示内容が更新され、localStorageに保存される

#### UC-03 タスクを削除する
- 事前条件: 削除したいタスクのカードがボード上に存在する
- 操作手順:
  1. カードの削除ボタン(または編集モーダル内の削除ボタン)を押す
  2. 削除確認ダイアログが表示される
  3. 「削除する」を選択する
- 事後条件: カードがボードから削除され、localStorageからも削除される

#### UC-04 タスクの進捗を更新する
- 事前条件: 移動したいタスクのカードがボード上に存在する
- 操作手順:
  1. カードをドラッグし、移動先の列にドロップする
- 事後条件: カードのステータスが移動先の列に応じて更新され、localStorageに保存される

#### UC-05 同一列内でタスクの表示順を変える
- 事前条件: 同じ列内に2件以上のカードがある
- 操作手順:
  1. カードをドラッグし、同じ列内の別の位置にドロップする
- 事後条件: 列内の並び順が更新され、localStorageに保存される

#### UC-06 期限切れ・期限間近のタスクを確認する
- 事前条件: 期限が設定されたカードが存在する
- 操作手順:
  1. ボード画面を開く、または表示を更新する
- 事後条件: 期限切れ・期限間近のカードが強調表示(色や枠線等)されて確認できる

## 3. 機能要件

### 3.1 カード(タスク)のCRUD操作

| 機能 | 内容 |
|---|---|
| 作成 | タイトル・説明文・優先度・期限を入力してカードを新規作成する |
| 編集 | 作成済みのカードの内容(タイトル・説明文・優先度・期限)を修正する |
| 削除 | 不要になったカードを削除する |

### 3.2 カードの移動・並び替え

| 機能 | 内容 |
|---|---|
| 列間移動 | ドラッグ&ドロップで「未着手」「作業中」「完了」の列(カラム)間をカードを移動できる |
| 並び替え | 同じ列内でドラッグ&ドロップによりカードの表示順を並び替えできる |

### 3.3 進捗状況(ステータス)の列構成
列(カラム)は以下の3つで固定とする。ユーザーによる列の追加・編集・削除は不要。

1. 未着手
2. 作業中
3. 完了

### 3.4 表示に関する機能
- 優先度が一目でわかるように、色分けなどで表示する
- 期限が近い、または過ぎているカードを強調表示する

### 3.5 データの永続化
- ブラウザを閉じても、再度開いたときに登録済みのカード情報が残っていること

## 4. 画面仕様

### 4.1 画面構成
本アプリは以下の2つの画面(状態)で構成する。

| 画面 | 概要 |
|---|---|
| ボード画面 | アプリ起動時に表示するメイン画面。「未着手」「作業中」「完了」の3列とタスクカードを表示する |
| タスク編集モーダル | タスクの新規作成・編集を行うための入力フォーム(ボード画面上にオーバーレイ表示) |

### 4.2 ボード画面

- 画面上部にアプリタイトルを表示する
- 画面中央に3つの列(未着手/作業中/完了)を横に並べて表示する
- 各列には以下を表示する
  - 列名(見出し)
  - 列内のタスクカード一覧(縦に並べる)
  - タスクを新規追加するためのボタン
- 各タスクカードには以下の情報を表示する
  - タイトル
  - 優先度(色分け表示)
  - 期限(設定されている場合。期限切れ・期限間近の場合は強調表示)
- カードをクリックするとタスク編集モーダルを開く
- カードはドラッグ&ドロップで列間移動・同列内並び替えができる

### 4.3 タスク編集モーダル

新規作成時・編集時で共通の画面とし、以下の入力項目を持つ。

| 項目 | UI部品 | 備考 |
|---|---|---|
| タイトル | テキスト入力 | 必須項目であることが分かる表示にする |
| 説明文 | 複数行テキストエリア | 任意項目 |
| 優先度 | セレクトボックス(高/中/低) | 必須。デフォルト値は今後の設計で決定 |
| 期限 | 日付入力(datepicker等) | 任意項目 |

- 「登録」または「更新」ボタンで保存し、モーダルを閉じてボード画面に戻る
- 「キャンセル」ボタンで変更を破棄してモーダルを閉じる
- 編集時のみ「削除」ボタンを表示する
- 入力値の詳細なバリデーションルール(文字数上限、エラーメッセージ文言等)は基本設計フェーズで定義する。本書では「タイトル・優先度は必須項目である」という要件レベルの制約のみを定義する。

### 4.4 画面遷移

```
ボード画面 --(新規追加ボタン押下)--> タスク編集モーダル(新規作成モード) --(登録/キャンセル)--> ボード画面
ボード画面 --(カードクリック)--> タスク編集モーダル(編集モード) --(更新/削除/キャンセル)--> ボード画面
```

## 5. カード(タスク)のデータ項目定義

| 項目名 | 必須/任意 | 型 | 備考 |
|---|---|---|---|
| タイトル | 必須 | 文字列 | 空では作成不可 |
| 説明文 | 任意 | 文字列(複数行) | 未入力可 |
| 優先度 | 必須 | 高 / 中 / 低 の選択式 | |
| 期限 | 任意 | 日付 | |
| ステータス | 必須 | 未着手 / 作業中 / 完了 | カード作成時のデフォルトは「未着手」 |
| 並び順 | システム管理 | 数値など | 同一列内の表示順を保持するための内部データ |

※担当者(アサイン)の項目は持たない(1人利用のため不要)。

## 6. 非機能要件

### 6.1 動作環境・互換性
- 対応ブラウザは最新版のGoogle Chromeを主とし、動作確認もChromeで行う(学習目的のため、他ブラウザでの動作保証は不要とする)
- PC(デスクトップ)のブラウザでの利用を前提とし、スマートフォン等でのレイアウト最適化(レスポンシブ対応)は必須としない
- インターネット接続不要でローカルで動作すること

### 6.2 性能要件
- タスク件数は個人利用を想定し、最大でも数十件程度の登録・表示を想定する。大量データ(数百件以上)でのパフォーマンスは考慮しない
- カードの作成・編集・削除・ドラッグ&ドロップ操作に対して、体感的な遅延なく(1秒未満を目安に)画面へ反映されること

### 6.3 データの永続化・信頼性
- サーバー・データベースを別途構築せず、ブラウザの localStorage にデータを保存する
- ブラウザを閉じても、再度開いたときに登録済みのカード情報が残っていること
- localStorageの特性上、以下はリスクとして許容し、特別な対策は行わない
  - ブラウザのキャッシュ・サイトデータを削除するとタスクデータが失われること
  - 別のブラウザ・別の端末からは同じデータを参照できないこと
  - localStorageの保存容量上限(ブラウザごとに数MB程度)を超えるデータは保存できないこと

### 6.4 ユーザビリティ
- Trelloのようなカンバン形式のUIに馴染みがあれば、説明なしで直感的に操作できることを目指す
- 優先度・期限切れ等の重要な情報は色分けや強調表示で視覚的に分かりやすくする

### 6.5 セキュリティ
- ログイン機能を持たないため認証・認可は考慮しない
- 入力値をそのまま画面に表示する箇所では、XSS(スクリプトインジェクション)が発生しないよう、入力値のエスケープ処理を行う

### 6.6 保守性・拡張性
- HTML/CSS/JavaScriptのみで完結する構成とし、ビルドツールやフレームワークの導入は必須としない(学習目的のため、シンプルな構成を優先する)
- 将来的な機能拡張(複数ユーザー対応、サーバー同期等)は本要件には含めないが、拡張しやすいようデータ構造と画面処理はある程度分離しておくことが望ましい

## 7. スコープ外(今回は対応しない事項)

- 複数ユーザーでの共有・ログイン機能
- 担当者(アサイン)機能
- 列(カラム)自体の追加・削除・名称変更
- スマートフォン等、別端末とのデータ同期(あくまで同一ブラウザ内での保存)
- 通知機能(期限が近づいたときのアラート等)

## 8. 技術選定

保守・引き継ぎの材料となるよう、実装に使用する技術要素を明記する。

### 8.1 フロントエンド

| 項目 | 選定内容 | 備考 |
|---|---|---|
| マークアップ・スタイル | HTML5 / CSS3 | |
| プログラミング言語 | JavaScript (ES6+) | TypeScript等の型付き言語は使用しない |
| フレームワーク | 使用しない(Vanilla JS) | 学習目的のため、フレームワークに頼らず素のJavaScriptで実装する。アプリの規模も小さく、フレームワーク導入の必要性は低い |

### 8.2 主要な機能の実装方針

| 機能 | 使用する技術 | 備考 |
|---|---|---|
| ドラッグ&ドロップ | ブラウザ標準の HTML5 Drag and Drop API | 外部ライブラリ(SortableJS等)は使用せず、標準APIのみで実装する |
| データ永続化 | ブラウザ標準の Web Storage API(localStorage) | |
| 日付入力 | HTML標準の `<input type="date">` | 専用の日付選択ライブラリは使用しない |

### 8.3 ビルド・開発環境

| 項目 | 選定内容 | 備考 |
|---|---|---|
| ビルドツール | 使用しない | webpack/Vite等のバンドラーは導入せず、作成したHTML/CSS/JSファイルをそのままブラウザで開いて動作する構成とする |
| パッケージマネージャー | 使用しない | npm/yarn等は導入しない。外部ライブラリに依存しないため不要 |
| バージョン管理 | Git / GitHub | ソースコードの管理に使用する |
| データベース・サーバー | 使用しない | |

### 8.4 技術選定の理由
- 学習目的のプロジェクトであり、フレームワークやライブラリに頼らず素の実装力を身につけることを優先する
- 外部依存が少ないほど「HTML/CSS/JavaScriptの基礎知識があれば誰でも読める」状態を保てるため、保守・引き継ぎの観点でもシンプルな構成を選定する
- アプリの規模(1人利用、タスク数十件程度、画面2つ)を踏まえ、フレームワークやビルドツールを導入するメリットよりも学習コスト・保守コストの増加というデメリットが上回ると判断した
